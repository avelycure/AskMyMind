# AI-ревью pull request

`.github/workflows/ai-review.yml` запускает `scripts/ai-review.mjs` при открытии и обновлении PR из ветки этого репозитория. Скрипт получает список файлов и diff, ищет подходящие фрагменты документации и исходного кода базовой ветки (локальный RAG), отправляет их OpenAI-совместимой модели и создаёт или обновляет один комментарий в PR. В комментарии модель должна указывать потенциальные баги, архитектурные проблемы и рекомендации с ссылками `файл:строка`. Вывод модели следует проверять вручную.

## Настройка

1. В GitHub откройте **Settings → Secrets and variables → Actions**.
2. Создайте секрет `AI_REVIEW_API_KEY` с ключом OpenAI-совместимого облачного API. Ключ не сохраняется в репозитории.
3. При необходимости задайте переменные `AI_REVIEW_BASE_URL` и `AI_REVIEW_MODEL`. Значения по умолчанию: `https://api.openai.com/v1` и `gpt-5.4-mini`. Для другого провайдера укажите его HTTPS-адрес API и идентификатор модели.
4. Откройте PR из ветки этого репозитория. После первого попадания скрипта в базовую ветку новые PR будут получать автоматическое ревью. Первый PR, который добавляет сам пайплайн, проверяется вручную обычными проверками.

Запуск с fork-репозитория пропускается: GitHub не передаёт секреты такому PR. Черновики также пропускаются до события **Ready for review**. Отсутствие ключа в обычном PR приводит к понятной ошибке задания, а не к фиктивному «успешному» ревью.

## Как работает контекст

RAG здесь означает локальный поиск релевантных фрагментов кода и Markdown-документации по словам из diff и путей изменённых файлов. Он не использует индекс личного Obsidian-хранилища и не требует отдельной модели эмбеддингов. Отбираются только отслеживаемые Git файлы базовой ветки; сборочные результаты и `package-lock.json` исключены. Размер diff и контекста ограничен, поэтому крупный PR может получить неполное ревью — в этом случае части diff явно помечены как опущенные.

Workflow исполняет скрипт из базовой ветки. Коммит PR скачивается только для чтения diff, его код не запускается. Перед публикацией проверяется, что PR не обновился во время анализа. Повторный запуск обновляет предыдущий комментарий бота, не создавая дубликатов.

Проверка локальной логики: `node --test scripts/ai-review.node-test.mjs`.

## Демонстрация для задания

На видео достаточно показать PR с небольшой намеренной ошибкой, страницу запуска **AI PR review**, затем комментарий с замечанием и ссылкой на строку. В кадре не показывайте страницу секретов или значения ключей. Код пайплайна находится в `.github/workflows/ai-review.yml` и `scripts/ai-review.mjs`.
